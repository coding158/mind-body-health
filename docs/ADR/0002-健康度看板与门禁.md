# ADR-0002 · 健康度看板必须被生成，且门禁不拦债务上升

**状态**：✅ 已接受　**日期**：2026-08-01

---

## 背景

治理层建立后（[ADR-0001](0001-知识模型经FAQ试点修订.md)），出现两个可预见的失效模式：

1. **手工维护的健康表一定会腐烂。** 而本仓的全部卖点是「它会诚实告诉你哪里没做好」——
   **一张过期的诚实表比没有表更糟，因为它把"假装完成"制度化了。**
2. **闭环需要能量输入。** `FAQ → 暴露缺陷 → MODEL → ADR → 新 FAQ` 这张图有个问题：**新 FAQ 从哪来？**
   若只能来自维护者自己，**这不是自我演化，是单人产能循环**。

## 决策

### 1. `HEALTH.md` 只能被生成，不能被手写

由 `scripts/health.py` 生成，文件头写明"请勿手工编辑"。
**债务不记在单独清单里**——清单会与正文脱节；**就地标记在出问题的那一行旁边**，由脚本捡取：

```
<!-- DEBT: type=citation | ref=3.2节两条M3 | opened=2026-07-31 | note=文献待补 -->
```

五类：`citation` 文献待补 / `gap` 材料缺口 / `conflict` 未裁断冲突 / `model` 模型缺格 / `stale` 超期未复核。

### 2. 门禁只拦「形式退化」，**不拦「债务上升」**

CI（`.github/workflows/health.yml`）：PR 跑 `--strict`，只在**坏链**或**覆盖率下降**时失败。

> **为什么债务上升不算失败**：把"债务只降不升"设成门禁，会诱导人**不标债**、甚至**不写新东西**——
> 那正好毁掉这个仓的卖点。
> 所以看板头部写死一句：**发现并标注债务是成果，不是失分。**
> **真正该报警的是「新增了内容，却零新增债务」**——那通常意味着没人在认真找问题。

### 3. 机械指标只测形式，正确率靠人工反问审核

**一页可以 100% 有「来源坐标」而每条都标错。**

| | 负责什么 |
|---|---|
| **HEALTH.md（机械）** | **覆盖率**——有没有标、通不通、还没还 |
| **季度反问审核（人工）** | **正确率**——每季随机抽 3 条声明反查原文，结果记入 ADR |

**两者不可互相替代。**

### 4. 开放外部输入

`.github/ISSUE_TEMPLATE/` 两份模板：`question.yml`（提现代问题）与 `defect.yml`（报告证据缺陷）。
后者更重要——**它把「反问审核」开放给外人：任何人都可以指出某条声明的坐标标错了，不需要先获得信任。**

### 5. 能力六命名为 **Governed Iteration**，不叫 Self-improvement

**仓库不会自己变好。** 它能做到的只是：**让人改它的时候改不坏，且每次犯错都留下规则。**
叫 Self-improvement 会被误解成「AI 自动维护」。

### 6. 闭环必须有退出条件

**一个主题的 FAQ，连续两轮外部反馈都没有暴露新缺陷 → 标记「稳定」，转入维护。**
否则闭环会变成永久返工。与本仓对数字校勘阶段的判断一致：**新增越来越少、稳定性越来越重要。**

## 后果

- ✅ 健康表不会腐烂（生成物 + CI 定时刷新）。
- ✅ 债务与正文同生共死（就地标记，改内容时一眼看见）。
- ✅ 外人可自证合规 → 才敢收 PR。
- ⚠️ **期初覆盖率很低（坐标 13.3% / 理由句 35.4%）**，因为判据把 `navigation/` 四页纳入分母，
  而那四页成文早于知识模型、从未标注坐标。**这笔债一直在，只是之前没被量出来。**
  **正确反应是承认基线并逐页补标，不是把判据改窄。**

## 一处实现细节（**勿删，删了会误报**）

`scripts/health.py` 的 `mask_code()`：扫描前把**围栏代码块与行内代码**用空格盖掉（保持字符位置）。

> **两次实测教训**：不做掩码时，规范文档里**讲解**债务标记写法的那些示例，会被计成真实欠债。
> **统计某个标记的指标，必须先排除"讲这个标记"的文本。**

## 修订 · 2026-08-01：观察静默天数改用 `OBSERVED` 字段

**CI 首跑当天即暴露判据缺陷，且是本次治理提交自己造成的。**

原判据用「最后一次**触碰**该文件的 commit」计算静默天数，于是**治理性编辑同样会清零**——
为标记债务在三份记录里各加了一行 HTML 注释，
**素食 59 天🟡 / 茶 58 天🟡 当场变成 0 天，警告被抹掉**，而那两份记录实际两个月无新条目。

**修法**：每份实践记录内放 `<!-- OBSERVED: YYYY-MM-DD -->`（或 `none` 表示尚无条目），
由本人在新增观察条目时更新；**无此字段才回落 git log，并在看板「取自」列标注 `git兜底`**。

**为什么这个方向是对的**：两种判据的**失效方向相反**——
- git 判据失效时**装好**（有人碰一下文件，警告消失）；
- `OBSERVED` 判据失效时**报警**（忘了更新，天数继续涨）。

**宁可失效成报警，不可失效成装好。** 存量六份记录已据 git 历史回填初值（回填来源已在各文件内注明）。

**并记一条写法禁令**：`DEBT` 的 `note` 中**不得出现 HTML 注释结束符**——
否则外层注释被提前截断、说明在看板里被悄悄切掉一半（本次踩过一次，看板照常渲染、不报错）。

## 触发条件（何时重开此议）

- 若 `--strict` 频繁误伤正常 PR → 重新审视判据，**但不得为通过而放宽**；
- 若外部 issue 长期为零 → 说明"开放输入"未生效，届时另议如何触达，而非放松质量要求；
- 若季度反问审核连续两次未发现坐标错误 → 可考虑降低抽检频率。
