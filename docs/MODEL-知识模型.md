# 知识模型 · Knowledge Model
# 这个仓库里的每一句话，来自哪里、能支持什么、冲突时怎么办

> **两条核心原则**
>
> ## 一、不同来源的知识，不互相**冒充**。
> ## 二、不同来源的知识，不互相**升级**。
>
> 第一条管**横向**：E3 不得写成 E2，个人体会不得写成古籍原文，转述不得写成实录。
> 第二条管**纵向**（**禁止证据漂移 · Evidence Drift**）：一条知识**不会因为被引用、被复述、被多人重复、或被另一侧的材料"印证"，就升到更高等级**。
>
> 本仓最大的价值不是"古籍指导现代生活"，而是**始终告诉读者：这句话来自哪里、有多硬。**

### 为什么要单列第二条

冒充是**明目张胆**的，升级是**悄悄发生**的——后者更常见，也更难发现。典型三种：

| 漂移写法 | 实质 | 为什么是错的 |
|---|---|---|
| "100 人反馈喝某茶后睡眠改善，**因此说明有效**" | **E4 → M3** | 个案再多也只是个案的堆叠——无对照、无随机、有幸存者偏差；样本量增加**不产生**因果强度 |
| "老子这样说，现代研究也这样说，**所以证明老子是对的**" | **E2 → M** | 现代研究支持的是**那个现代命题**，不回溯证明古籍读法；这是把并列关系偷换成因果关系 |
| "这是**系统综述**，所以是最高级证据" | **M3 → M1** | 综述的等级取决于**它纳入了什么**：纳入大量个案与观察研究的综述，仍是 M3 |

> **判断口诀**：问一句「**如果去掉这次引用/复述/印证，这条知识本身的等级变了吗？**」
> 答案永远是「没变」。**变的只是它被说起的次数。**

## 1. 这个仓库有哪些类型的知识（Q1）

**两条独立坐标轴**，任何一条内容都同时有两个坐标——**不要把它们混成一个"可信度"分数**。

### 轴一 · E：本仓自身产出的知识来源层级

| 级 | 内容 | 可回溯性 | 典型位置 |
|---|---|---|---|
| **E1** | **古籍原文与校勘** —— 帛书甲乙本、通行本、异文对照、字形勘定 | **最高**（可逐字核原件影印/释文） | `classics/taoism/道德经第五章-版本对照.md`、各章页「原文」节 |
| **E2** | **他人已有的解释**——**忠实转述，出处可回溯**。**必须分三档，见下** | 高（可查原书页码） | 各章页「关键字义」节，标注如《破译》p.247 |
| **E3** | **项目组自己的东西**——**必须分两档，见下** | 中（依赖论证质量） | 章页「义理串讲」、`navigation/`、`faq/`、`SQ/`、本文件 |
| **E4** | **实践观察、案例、个人经验** —— 具名个人的亲身记录 | 较低（n=1，无对照） | `practice-records/` |

#### E2 的三档：谁在说这句话

| 档 | 是什么 | 例 |
|---|---|---|
| **E2a** | **通行 / 主流读法** —— 历代注家与通行本的共识 | 「反者道之动」＝返归、相反是道的运动 |
| **E2b** | **少数派或个人勘定读法** —— 某一家自成体系的读法，与主流不同 | 干昌新勘定本读「反」为**反馈**、读「清静」为「請靚」 |
| **E2c** | **其他传统的说法** —— 中医、佛教、瑜伽等**非本仓古籍正文**的传统主张 | 「禅茶一味」、中医的「肝火」「心肾不交」 |

> **⛔ 硬规则**：**E2b 与 E2c 不得单独支撑原创结论的核心论点**——
> 必须与 **E2a** 或 **M 轴**并列出现，且注明这是哪一家的读法／哪一个传统的说法。
>
> **为什么**：一家之言可以很有启发，但**把整栋楼盖在一个未标记的少数派读法上，地基是不可见的**。
> 并列出现不是为了"平衡"，而是让读者看得见**这一步依赖的是谁**。

> **⚠️ 这条规则的适用面（重要，勿扩大）**
> 它只约束**产出原创结论的页面**——`faq/`、`research/`、`cases/`、以及 `navigation/` 中的原创段落。
> **它不适用于 `classics/` 下的章页，也不回溯适用于《德经》68 篇。**
> 理由：章页的任务本就是**忠实转述某一家的读法**，不是产出原创结论；它们已经在页内标明「观点转述」与出处，
> **这正是 E2b 的正确用法，不是违规。** 若发现"必须改章页才能自洽"，那说明**规则边界写错了，不是章页写错了**。

#### E3 的两档：本仓自己的东西也分轻重

| 档 | 是什么 | 可信度依赖 |
|---|---|---|
| **E3a** | **基于 E1/E2 的归纳** —— 串讲、编排、把已有材料整理成结构 | 依赖底下那层材料是否可靠 + 归纳是否忠实 |
| **E3b** | **项目组原创分析** —— 本仓自己提出的解释、模型、假设 | **只依赖自身论证质量**，没有更底层的材料背书 |

> **为什么要拆**：不拆的话，**原创分析会悄悄借 E1/E2 的光**——
> 读者看到「E3」，以为背后有古籍或原书撑着，实际上那一段是本仓自己想的。
> **这正是第二条核心原则要防的漂移，只是发生在本仓内部。**
> 第五层将来的「原创模型」几乎全是 **E3b**，**必须标清楚**。

### 轴二 · M：现代研究证据等级

| 级 | 内容 |
|---|---|
| **M1** | 系统综述 / 临床指南 |
| **M2** | 随机对照试验 |
| **M3** | 观察性研究 |
| **M4** | 专家意见 / 机制推论 |
| **M5** | **暂无现代证据** |

### 轴三 · R：权利与可传播性（**独立轴，勿与证据混同**）

沿用 `tools/generate_catalog.py` 的既有分级：**🟢A 公版 / 🟡B 不确定 / 🔴C 版权期内**。

> **为什么必须独立成轴**：这是审计中的实证——**一本 🔴C 类现代著作可以承载 M1 级证据，一份 🟢A 类公版原文往往是 M5**。
> **"能不能公开全文"与"可信度多高"是两回事**，混为一谈会同时犯两种错。

## 2. 每一种知识来自哪里（Q2）· 标注写法

**任何一条实质性说法，都应能回答"这是 E几 / M几"。**

### ⚠️ 标注粒度：段落级是默认，句级明确不做

| 粒度 | 做不做 | 说明 |
|---|---|---|
| **段落级 / 小节级** | ✅ **默认** | 一个小节或一段论证下挂一个标注块；这是唯一被要求的粒度 |
| **文末坐标总表** | ✅ **推荐** | 让读者一眼看出全页哪条最硬、哪条最软（`faq/` 首篇已示范） |
| **句级逐句标注** | ⛔ **不做** | 实测：一段话常同时含 E2＋M4，逐句标注写不下去，且会把可读性彻底压垮 |

> **粒度落在段落，不落在句子。** 若一个段落里混了两种来源且强弱悬殊，
> **正确做法是把它拆成两段**，而不是在句子上贴标签。

推荐标注块：

```
> 来源：E2（干昌新原书观点，《破译》p.247，忠实转述）
> 现代证据：M5（暂无直接研究）
> 适用：帮助理解该章读法；不构成健康建议
```

再如：

```
> 来源：无古籍对应
> 现代证据：M1（CBT-I，多国指南一线推荐）
> 适用：可作为慢性失眠的行动建议
```

**本仓已在实践的等价写法**（不必改造，认作同一体系即可）：

- 章页：「以下均为**观点转述**」＋页码 → 即 **E2**；「本章依据不算厚，本页照实说明」「原书零改笔、零注疏」→ **E2 弱**
- 导航页：🟢较充分／🟡部分相关／🔴几乎没有 → 覆盖度，非证据级；每条必附「**为什么是这一条**」→ 论证可核
- 导航页第三节「现代常见的解释路径」→ **M 轴内容**，与古籍**并列呈现**

## 3. 每一种知识能支持什么、不能支持什么（Q3）

**这一节是全文最要紧的一节。**

| 级 | ✅ 能支持 | ⛔ 不能支持 |
|---|---|---|
| **E1** | 「原文作何字」「某本与某本此处不同」 | 「因此应当这样做」——**校勘不产生行动建议** |
| **E2a** | 「历代大致这样读」 | 「因此事实如此」——读法共识不等于事实 |
| **E2b** | 「**某一家**如何读这一句」 | 「这就是老子本意」；**不得单独支撑原创结论的核心论点** |
| **E2c** | 「**某个传统**有这样的说法」 | ⛔ 任何健康主张；**不得单独支撑原创结论的核心论点** |
| **E3a** | 「本仓如何理解、如何编排已有材料」 | 冒充 E1/E2 的确定性；**不得把归纳讲成原文或原书观点** |
| **E3b** | 「本仓自己提出的分析与假设」 | ⛔ **不得借 E1/E2 的光**——必须标明这是本仓原创，没有更底层材料背书 |
| **E4** | 「**某个具名的人**经历过什么」 | 「因此这有效」「你也可以这样」——**n=1、无对照、有幸存者偏差** |
| **M1–M2** | 健康与行为建议 | 超出研究人群与条件的外推 |
| **M3–M4** | 提示方向、生成假设 | 当作定论 |
| **M5** | **什么都不能支持** | **凡涉健康主张，M5 一律不得单独成立** |

### 三条硬规则

1. **E4 永不升级为 M。** 实践记录再多、再一致，也不会变成研究证据——**它只增加"有人这样经历过"的样本，不增加因果强度**。
2. **E1–E3 不产生健康建议。** 古籍读法是**理解框架**，不是依据（`navigation/README.md` 已明写此分工）。
3. **凡"可能致伤"的内容（断食、憋气、剧烈体感、停药），无论 E 几，一律附前提与警示，并优先给出就医/求助路径。**

## 4. 冲突时怎么办（Q4）· 并列，不合并

> **冲突不是要消除的瑕疵，冲突本身就是信息。**

| 冲突类型 | 处理 | 本仓既有先例 |
|---|---|---|
| **E2 内部**（同一解释体系两书打架、或作者自相矛盾） | **专列一节说清**，不塞进串讲含混带过 | 系列总目所记第十八篇「两书冲突」、第二十篇「内部不一致」 |
| **E2 与通行注家**（如「反者道之动」：反馈 vs 返归） | **两读并存，各标出处**，不裁断谁对 | 德经第七章页；`SQ/` 维度四已加注「此处取通行读法」 |
| **E（古籍）与 M（现代）** | **并列呈现，不混为一谈**，各标出处，让读者自己称量 | 导航页固定第三节的做法 |
| **⚠️ 涉及健康与安全时** | **M 轴优先，并明说。** 这是唯一一条"分高下"的规则 | `sleep.md`：「CBT-I…**比本仓任何一篇古籍解读都有用**」 |

**禁止的三种消解方式**：

- ❌ 「其实说的是一回事」——用模糊措辞把冲突抹平；
- ❌ 用现代研究去"证明"古籍（把 M 当作 E 的背书）；
- ❌ 用古籍去"补上"研究的空白（把 E 当作 M 的替代）。

> **缺口留在原处，不抹平。** 这是本仓一贯做法（`sleep.md` 整页就是这条原则的实例：核对后没有对应章节，就直说没有）。

## 4b. 第三种状态：**X · 已排除**

E 轴与 M 轴回答"这条知识**有多硬**"，但仓里还有一类内容，它的状态是「**查过了，不成立**」——
既不是"有证据"，也不是"暂无证据"，而是**已经被排除**。**它必须有自己的格位，否则会被反复重新捡起来。**

| 记号 | 含义 |
|---|---|
| **X1** | **配对错误**——看起来相关，核对后发现讲的是别的事（"字面像、其实不是"） |
| **X2** | **事实错误**——曾经写过、后经核对确认为误，已订正 |
| **X3** | **流行但不成立的说法**——外界常见，本仓明确不采用 |

**本仓已有的排除记录（本次升格进模型，原文仍在各自页面）**：

| 例 | 记号 | 出处 |
|---|---|---|
| 赛斯《灵魂永生》「睡眠」命中 101 次，实为**做梦与出体**，与失眠无关 | **X1** | `docs/AUDIT-书库与导航页对应.md` |
| 奥修文集「饥饿」多为**「对真理的饥饿」**等隐喻 | **X1** | 同上 |
| 「反者道之动」曾被挂到 `daodejing-ch5.md`（橐籥章）——实为通行本第 40 章，分属道经与德经 | **X2** | 2026-07-31 订正 |
| 「烦躁说明你修错了 / 根器不够」 | **X3** | `faq/why-restless-when-still.md` 第二节 |

> **为什么必须单列**：`navigation/README.md` 说「这类错误是这个目录最要命的错误」——
> **排除过的配对，如果不留痕，下一个人（或下一个 AI）会按同样的字面相似度重新配一次。**
> **排除本身就是成果，值得和结论一样被保存。**

## 6. 落到新模块上（供后续 `cases/` `faq/` `research/` `templates/` 采用）

- **`cases/`（E4）**：每则须含**具名或可追溯、完整前提、失败与中断也要记、明确"不建议模仿"边界**。
  **无这些的案例＝见证式内容（testimonial），本仓不收。**
- **`research/`（M）**：每条必须标 M1–M5，**并允许结论是「M5：暂无证据」**——写出"没有研究"与写出"有研究"同样有价值。
- **`faq/`（E3 为主）**：回答现代问题；凡触及健康，须给 M 轴信息与就医边界。
- **`templates/`（工具，非方案）**：只回答"**如果你已经在实践，可以记什么**"，
  **不回答"你该做什么"**——这正是本仓不设 `protocols/` 的原因：**目录名一旦写成「3天轻断食」，就等于推荐**。
